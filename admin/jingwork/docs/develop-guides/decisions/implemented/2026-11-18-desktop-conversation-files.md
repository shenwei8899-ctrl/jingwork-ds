# 桌面对话交付文件同步

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/desktop_conversation_file_service.py

## 问题

后台聊天记录只有桌面文字副本，生成并交付的文件仍依赖客户端本机。管理员需要在所属对话中查看和下载文件，客户端离线后仍可访问已同步副本。

## 决策

桌面从已提交的文件交付事件及成功文件修改结果读取文件身份及所属 Session，使用已绑定账号上传文件副本。成功 `write`、`edit` 和 `str_replace_editor` 修改命令复用桌面文件卡片的路径解析规则，调用与成功结果以 callId 关联，读取、失败调用和普通工具输出不产生文件。后台使用用户、设备、专家和线程关联会话，在会话下方列出文件名、大小、生成时间及下载入口。

### 实现方案

桌面同步 Worker 在文字确认后读取文件，交付和修改分别确认游标。缺少修改游标的旧账本从历史起点补传修改产物，保留既有交付确认；分页跨过已确认位置时继续读取尚未配对成功结果的调用记录。后端 service 校验完整会话归属与内容哈希，repository 持有不可变文件元数据，私有 MinIO 保存内容。相同来源重试返回既有确认，不覆盖不同内容。对象上传成功、数据库提交成功后才确认。数据库提交失败时对象使用确定键保留供重试复用。

管理员查询与下载均经过后端鉴权，文字与文件上传均要求登录。下载使用附件响应，文件名只作为显示名称，客户端路径不作为服务端路径。缺失本机文件或上传失败保留文件游标供后续重试，文字同步持续推进。每个已确认文件的来源 ID 单独持久化，部分失败时仍继续上传其他文件，重启后跳过已确认文件；本次读取的待传文件全部确认后推进文件游标。

## 替代方案

只记录本机路径会在客户端离线时失效。扫描整个目录无法可靠确定文件属于哪个会话，交付事件和成功文件修改结果拥有明确来源。只同步 `present` 会遗漏桌面已显示的文件工具产物。

Mac Apple Silicon 安装包已构建，离线运行时与 Office smoke 通过，公开下载支持 HTTP Range。本机客户端已更新并在用户完成 macOS 钥匙串授权后恢复；自动同步的文件游标已越过历史交付事件，后台回读仍为两份文件且内容哈希保持一致。Windows 构建命令因缺少 Windows x64 构建机退出，未产出新版安装包。深色主题未验证。

成功文件修改同步的修复版客户端已安装，真实会话中的一份 418 字节 TXT 通过客户端自动补传；后台页面展示、原账号/设备/专家/Session 归属和私有存储内容哈希均已核对。该验收没有通过管理通道插入文件。

全仓 `doc-sync` 的 43 项检查通过。管理端工程信任检查存在 73 个其他决策记录和 workflow 问题，本文件未产生检查错误；管理端独立文档站构建受已有三处 `design-qa` 死链阻塞。

## 后果

新客户端才能补传本机仍存在的历史交付文件。交付后被改写的历史文件只能读取当前本机内容。单个文件上限为 100 MiB，失败保留可重试状态。

上传读取当前路径的文件内容。服务端已保存但客户端未收到确认时，如果文件又被改写，旧来源的重试会触发内容冲突并保持未确认；当前验证未覆盖此组合场景。

# Octop 专家与企业 Agent 双向集成

## 目标与边界

企业 Agents 页面新增内置专家、专家市场。管理员审核提示词及 Skills 后导入原生 Yuxi Agent，后续编辑、授权与执行沿用 Yuxi。桌面端新增企业智能体入口，与 Yuxi 使用同一账号登录。桌面登录验证 Yuxi 账号并按不可变 UID 建立本地 SSO 身份，自动使用该用户的加密会话；不提供第二次企业登录或 API Key 输入。

## 数据与权限

内置专家使用 Octop 公共 library 快照（MIT）；市场实时读取同一个 SkillHub API。排除桌面 default 模板。完整安装依赖后创建 Agent，失败清除本次已安装 Skill。Yuxi 要求 slug 时仅补充格式兼容元数据；不复制模型密码或桌面个人文件。导入 Skill 初始共享范围与 Agent 一致，之后 Agent 和 Skill 的权限仍分别使用 Yuxi 原生配置，扩展共享范围时应同时授权依赖资源。

桌面统一会话使用 Octop 现有加密存储并按用户隔离，地址改变不转发旧密钥；HTTP 仅允许本机地址，其他部署使用 HTTPS。每次列表和执行实时检查 Yuxi 权限，原生 Agent Call 经过队列和 worker，知识库、Skills、MCP 和模型配置保留在服务端。

## 界面

企业后台保留原生企业智能体列表，增加两个模板目录页，支持搜索、分类、刷新、审核、导入。桌面端保留我的专家/团队/内置专家/专家市场，增加企业智能体目录和真实调用对话框。企业 Agent 尚未映射为 Octop 本地 harness 专家，也没有同步桌面私有专家到公共市场。

## 验证

新增真实 HTTP/PG 测试：六个办公 Skill 与 Agent 同时落库、指定员工统一会话可见、未授权员工不可见、撤权后不能提交运行；部门共享 Agent 使用统一登录 JWT 经过真实 worker 调用临时 OpenAI 兼容测试模型并返回结果。临时模型不需要外部 LLM 密钥。

Octop 单元验证实际 SQLite 密钥加密、按用户隔离、地址切换与撤权、原生请求字段；另运行 i18n 回归与 Python strict 类型检查。生产模型和依赖软件可用性由部署配置决定，公共 Skill 文档中的桌面专用路径/工具不会自动变成 Yuxi 能力。

## 统一登录补充（2026-10-06）

当前桌面安装启用 `settings.yuxi_unified_login=true`，服务来源固定为 `OCTOP_YUXI_URL`。登录沿用桌面入口，账号 ID/手机号及密码由 Yuxi 校验；不按显示名合并旧账号，不同步密码哈希。每次桌面 HTTP 请求和 WebSocket 建连检查中央会话和账号状态，退出登录清除本地中央会话，过期后需要重新登录。桌面原本的本地账号和私有资源保留，未自动迁移；经过中央认证的管理员/超级管理员同步为桌面管理员，其他角色同步为桌面普通用户；每次认证复查角色，后台降权同步收回桌面管理员权限。身份不一致时先拒绝请求，不更新角色。

真实已安装桌面 HTTP 验证通过登录、身份、授权列表、撤权列表/调用及退出失效。原生 worker 使用中央 JWT 执行成功。Octop 相关认证回归 22 项通过；构建通过。全库 ship 检查仍被既有 `knowledge_indexes.py:933` 类型错误阻止。

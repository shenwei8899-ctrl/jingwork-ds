# 双向技能市场

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/octop_expert_service.py

## 问题

企业 Skill 管理与桌面端需要同源市场，并让当前统一账号能导入后台已授权的技能。

## 决策

后台从 SkillHub 技能集准备原生安装草稿，继续原有依赖审核、共享范围和安装确认。只下载技能，不创建 Agent。失败时清理已准备草稿。

桌面端从当前统一账号的后端会话读取启用且可读的共享技能，下载时再次查询授权，并在共享行锁下重新检查可读与启用状态。普通管理导出仍要求管理权限。

桌面端已有技能包属于实例全局。将受限技能复制到全局包会扩大可见范围，因此后台授权技能只能导入用户拥有的专家工作区；复用工作区原生安装与冲突检查。公共 SkillHub 的全局技能包导入保留。工具、MCP、知识库等运行依赖仍需配置，导入副本不持续同步后续修改或撤权。

## 替代方案

直接复制到全局包更简单，但不符合原分享边界。增加账号级全局包会引入新的存储与运行挂载语义，超出此次入口接通范围。

## 后果

授权技能的导入目的地限定为自己的专家工作区，不改变实例全局技能包的共享语义。

## 验证

真实 HTTP/PostgreSQL 测试验证允许读取的归档、未授权 404、停用 404。桌面端 HTTP 测试导入后重读工作区脚本，并验证重复导入不能覆盖。归档 unit 覆盖原文件、路径逃逸、符号链接与解压大小。前端检查市场列表和原公共导入入口。

# 企业知识库详情路由

状态：implemented
类型：bug-fix
Owner：web/src/router/index.js

## 问题

企业知识库列表保留详情入口，企业布局缺少对应子路由和内容出口，详情地址进入页面未找到提示。详情返回地址使用 `tab=knowledge`，企业页面选择使用 `page`，返回操作无法打开知识库列表。

## 决策

### 实现方案

路由在 `/extensions` 下注册知识库详情与评估基准详情，沿用现有组件、命名路由及 `kbId`、`datasetId` 参数。两条子路由继承企业入口的登录与管理员要求，权限守卫继续保留被拒绝的完整地址。

`EnterpriseConsoleView.vue` 通过路由名称识别知识库详情，使用按路径区分的 `router-view` 承载详情并选中知识库导航。页面识别现有返回地址 `/extensions?tab=knowledge`，让知识库、评估和删除操作共用知识库列表入口。该装配延续[企业知识库入口的复用决定](./2026-10-06-enterprise-knowledge-menu.md)。

## 替代方案

另建详情页面会复制文件、检索、图谱和评估能力。分散修改现有返回地址会扩大改动范围，且已经存在的深链接仍需要有效入口。

## 后果

企业知识库保留现有详情地址和操作能力。知识库记录、可管理状态和数据访问仍由现有 API 返回，前端管理员限制继续生效。

## 验证

`knowledge_navigation.test.js` 与知识库详情布局、评估工作区、账号导航共 16 项测试通过，覆盖路由解析、登录跳转、角色限制、详情承载与返回列表。加载缺失路由或旧布局的负向案例分别因目标缺陷失败。前端 lint 与构建通过，线上真实页面验证直接访问、列表卡片进入及返回列表。

全量前端测试仍有 `chatStartScreen.test.js` 断言失败与 `api_boundary.test.js` 文件级失败。工程契约检查存在缺失工作流和既有决策格式问题，其自身 63 项单元测试通过。

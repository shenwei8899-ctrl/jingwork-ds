# 企业概览与桌面对话日志统计

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/repositories/desktop_conversation_repository.py

## 问题

组织概览的 Web 会话与消息统计遗漏桌面使用情况。IAM 目录拥有企业账号总数，本地 User 保存已经建立应用身份的账号，直接使用本地账号数会低估目录成员。

## 决策

概览按已同步日志的用户、设备、专家、线程完整键统计累计会话，按已保存事件统计消息，并展示提问与回复数量。最近 30 天活跃成员按上海最近 30 个日历日至当前时间内有消息的用户去重。累计已同步成员按日志用户去重，最近同步时间取后台接收时间。历史日志保留软删除账号的记录，与日志页查询一致。

启用 IAM 时，组织成员总数取账号目录的分页 total。未启用 IAM 时，成员数取有效本地账号。智能体数量使用当前管理员在智能体管理页可见的定义，包含子智能体。

### 实现方案

日志 repository 拥有事件聚合及本地有效账号查询。Dashboard service 通过已有智能体可见性查询组合资源数量。管理员专用 overview HTTP 接口返回汇总与读取时间，普通成员请求返回 403。

概览独立读取企业资料、成员目录、日志汇总与已有知识库统计。局部请求失败显示缺失值和重试提示，其他成功数据继续展示。刷新重新读取来源。会话入口跳转到对话日志，成员入口跳转到权威目录。

## 替代方案

将桌面事件与 Web 消息合并需要跨来源去重规则，且当前对话日志无法复核混合总数。使用本地账号数作为 IAM 企业成员数会遗漏尚未登录应用的企业账号。

## 后果

概览和日志只覆盖桌面已经同步的素材。IAM 账号总数包含目录中的账号状态，近期活跃成员表达有消息记录的用户。知识库统计沿用已有超级管理员权限。

## 验证

真实 HTTP/PostgreSQL 测试 5 项通过，覆盖完整会话键、重复同步、消息分类、401/403、私有智能体可见性、空日志、本地软删除账号和固定时钟下的上海时间窗口边界。Dashboard 与权限单测 15 项通过，前端相关测试 10 项通过，lint、ruff、Web 生产构建和 diff 检查通过。

测试站页面与独立 PostgreSQL 分组查询逐项核对累计会话、消息、提问、回复和已同步成员。浏览器验证日志入口的会话总数及 IAM 成员目录分页，截图检查正常页面和长文案换行。

后台全量单测结果为 2519 通过、10 失败、58 跳过。失败集中于既有知识库、迁移和启动测试。工程信任检查报告既有 decision 元数据及缺失 workflow，文档构建报告三个既有 design-qa 链接错误。相关专项检查的通过结果与这些全量检查结果分别记录。

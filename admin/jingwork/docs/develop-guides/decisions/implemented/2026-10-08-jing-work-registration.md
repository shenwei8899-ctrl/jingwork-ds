# Jing Work 普通账号自助注册

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/registration_service.py

## 问题

Jing Work 桌面登录原本只支持登录与管理员创建账号。新增公开的账号 ID / 密码注册流程，注册成功返回登录页；新账号与管理后台使用同一个账号源。

## 决策

- `POST /api/auth/register` 只接受账号 ID 和密码。账号 ID 为 2–20 位字母、数字或下划线，以字母开头；密码为 8–64 个字符并包含字母和数字。
- `registration_service.py` 拥有注册事务，`UserRepository` 与 PostgreSQL 唯一约束拥有账号事实。账号、密码哈希、审计在提交成功后才对调用方确认。
- 注册只创建默认部门下的普通用户。客户端不能指定角色、部门或权限；缺少初始化或默认部门时明确拒绝。
- 沿用默认部门归属，保证既有 `get_required_user` 部门校验和登录后的业务流程成立。无部门账号方案会使注册成功后无法读取本人资料，因此未采用。
- 每 IP 每小时最多 10 次注册尝试，计数由 Redis 原子执行；数据库唯一约束收敛并发重复注册。
- 桌面统一登录启用时由账号服务注册，失败不创建本机替代账号。没有手机验证的能力，因此此次不提供手机号绑定或短信注册。

## 替代方案

无部门账号会被既有认证依赖拒绝，因此注册沿用默认部门规则。只增加本地账号会与统一登录的身份源脱节，因此统一登录启用时必须向账号服务注册。

## 后果

默认部门可容纳自助注册用户；注册不授予管理员权限或由客户端选择企业部门。手机号验证与邀请加入其他部门留在各自流程中。

## 验证

真实 HTTP / PostgreSQL 集成用例覆盖持久化角色、密码哈希、新账号登录及资料读取、管理员接口拒绝、重复与并发注册、非法身份字段和限速。测试账号与注册限速键在用例后清理。

桌面侧另验证注册字段校验、密码不一致、重复账号错误、注册后返回登录、本机模式及统一账号服务不可达时不降级。

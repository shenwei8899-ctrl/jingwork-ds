# 企业研效看板统计核对

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/enterprise_productivity_service.py

## 问题

研效看板使用 Web Conversation、Message 和本地 User 统计企业使用情况，遗漏桌面已同步对话及 IAM 目录成员。模型和 Token 曲线读取 Web 消息元数据，无法呈现统一模型调用账本。没有反馈时默认 100% 满意度形成错误度量。

## 决策

企业研效默认展示与组织概览、成员明细一致的累计会话、提问、消息、成员及实际 Token。日期窗口、每日趋势、成员排行、专家会话分布及模型用量使用相同的北京时间窗口。历史缺失 Token 保留缺失状态。Web 运行概览和会话分析保留明确标注的标签入口，满意度在零反馈时显示缺失值。

### 实现方案

企业看板 service 复用桌面概览和成员统计，组合 repository 的独立事件与调用聚合，IAM 人数来自成员目录元数据。所有数据库查询共享独立的 REPEATABLE READ 只读事务和统计截止时间，IAM 目录在请求中读取。HTTP 接口维持超级管理员授权。页面复用已有指标卡、图表与表格，提供刷新、来源及读取时间。已有 Web 查询与审计入口保留各自运行范围。

Web 活跃度使用可见消息的发生时间，工具成功率以成功和失败调用为分母。时间序列按北京时间完整小时、日或 ISO 周分桶，排除截止时间之后的记录，工具总数对应所选窗口。缺少元数据的模型回复归入未记录模型。趋势图保留缺失 Token 的空缺，稀疏数据点在长窗口中仍可见，提示使用精确整数。

## 替代方案

仅替换顶部数字会造成图表和排行继续遗漏桌面记录。将 Web 和桌面消息直接相加需要跨来源身份去重规则。按各自真实来源展示和核对可以保持当前明细可复核。

## 后果

桌面记录和实际模型用量具有各自采集起点，来源与最近同步时间随指标展示。历史 Token 缺失需要上游原始用量才能精确补全。累计会话覆盖全部已同步记录，期间会话在窗口内去重，每日活跃会话在各日独立去重。

## 验证

后台专项测试 24 项通过，覆盖真实 PostgreSQL 与 HTTP 的汇总、权限、日期窗口、同名线程、未来消息、SQL NULL 元数据、ISO 周和工具状态。并发写入屏障验证只读可重复读快照保持一致，独立连接确认写入已提交。

前端专项测试 8 项、lint、生产构建、ruff 与 diff 检查通过，覆盖未知和零 Token、迟到请求、刷新错误、长窗口稀疏数据点及整数显示。测试站在同一只读数据库快照中读取原始行，使用独立 Python 聚合核对 7、14、30、90 天的累计、期间、每日、专家、模型和成员合计。

桌面浏览器验证默认企业研效、日期切换、Token 单点、来源时间、刷新及成员和日志入口，Web 概览与会话分析读取成功，无反馈满意度显示缺失。页头在窄容器内换行。控制台现有 480px 以下布局隐藏主内容，手机验收受此布局限制。工程信任检查与文档构建存在既有 decision 元数据、缺失 workflow 和 design-qa 链接错误。

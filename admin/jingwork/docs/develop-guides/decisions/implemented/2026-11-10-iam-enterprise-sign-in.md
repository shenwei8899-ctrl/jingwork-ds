# 单企业 IAM 身份接入

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/iam_service.py

## 问题

企业后台的本地账号无法承接平台统一登录、管理员变更、员工停用和子系统准入。独立测试实例需要接受已登记企业的 IAM 身份，并在业务入口执行最新权限检查。

## 决策

### 实现方案

实例绑定一个配置化的 IAM 租户 UUID。BFF 使用客户端凭据交换授权码、自省和吊销，目录查询使用独立服务密钥。浏览器只保存 HttpOnly 会话 Cookie，Access Token 和 Refresh Token 保存在实例 Redis；state 与浏览器 Cookie 双向绑定并一次性消费。前端通过公开配置发现 IAM 入口，并从无授权码的完成页恢复用户状态。

IAM 平台管理员映射为 superadmin，租户管理员映射为 admin，其余映射为 user。每个受保护请求重新校验身份和子系统准入，拒绝其它租户。IAM UUID 派生独立本地 uid，避免与既有本地账号按姓名或邮箱合并。IAM 目录通过企业后台只读查询；本地主档继续承接业务对象的外键。IAM 是企业实例唯一用户认证入口。本地密码、注册、管理员初始化、账号创建修改删除、模拟登录和旧 OIDC 认证入口关闭，历史业务资源按原用户外键保留。

桌面与 CLI 的设备密钥关联 Redis 中的原始 IAM 会话，并同时检查数据库密钥有效性与实时自省。短期响应重放只能引用原会话。所有登录目标共用已登记的 `/sso/callback`，返回页面保存在服务端 state 记录。

平台入口使用已登记的子系统前缀。前端资源、路由与 API 请求采用同一部署前缀，网关只增加本子系统片段。

桌面模型目录通过 `/api/system/model-providers/desktop-catalog` 按当前账号策略过滤，只返回模型标识、名称和供应商标识。桌面将目录注册到现有模型适配器，调用经原生本地转发进入企业模型网关，服务端执行授权与额度检查。供应商密钥保留在服务端。模型设置页支持刷新目录及保存新会话默认模型，已有会话使用会话模型选择器。

## 替代方案

通用 OIDC 登录只在建立本地 JWT 时校验身份，不能承接 IAM 的逐请求自省和准入语义。全量多租户改造需要覆盖全部业务查询的租户隔离，超出单企业测试环境的验收范围。

## 后果

IAM 不可用时受保护请求拒绝执行。主动登出按照 IAM 文档触发全平台吊销，界面需告知范围。服务凭据与用户会话分别管理，凭据仅保存在运行环境。管理员准入依赖 IAM 可用性。

IAM 人员组织以分页只读目录呈现，本地业务用户归入企业成员组。知识库和其它资源的授权由蓝鲸自身配置控制，组织展示与资源授权分别维护。

## 验证

协议单元测试覆盖 state 绑定与重放、角色和租户校验、服务凭据分离、续期结果不确定和明确服务故障。独立 PostgreSQL schema 与真实 Redis 的 HTTP 用例覆盖 Cookie、Origin、权限变更、首次并发创建、旧 JWT 拒绝与设备会话撤销和刷新互斥；空员工姓名按 IAM 目录契约接受并使用工号展示。

前端检查覆盖前缀映射、目录请求取消与旧响应隔离、租户管理员避开全局统计接口，以及既有认证和 Markdown 请求。真实 IAM 验收覆盖三种角色的 SSO 与目录权限、刷新轮换和主动登出；浏览器验证统一登录回跳、组织目录和租户管理员概览。

# 后台对话模型同步到桌面

## 目标与边界

管理员在 Yuxi 维护对话供应商，统一账号登录的 Octop 桌面读取配置。保留桌面本地供应商及生成、语音、搜索配置，不将这些私有配置反向发布到后台。

## 数据与执行

`/api/system/model-providers/desktop-config` 使用原管理员认证，解析服务器环境变量凭证并只导出 chat 模型。固定来源的统一会话将配置投影到桌面 ProviderRepo，再重载 harness；模型调用使用桌面已有执行器。同步凭证进入桌面既有供应商存储，不进入前端响应。该机制与执行留在 Yuxi 的企业 Agent 调用不同。

桌面模型页打开期间每 15 秒刷新，重新聚焦或手动刷新也会拉取。管理员模型列表与模型选择接口触发同步；普通用户不读取中央管理员凭证。停用或删除中央配置会撤掉对应桌面可用模型；本地界面和 API 不允许修改同步供应商。

当前直接调用适配 OpenAI 兼容、OpenRouter、Anthropic。Gemini 原生协议、中央 UID 签名和模型级请求覆盖不能静默降级，遇到启用配置时明确拒绝同步。非 ASCII 或含内部空白的凭证不进入运行模型池；更新有效凭证后恢复。

## 证据

真实中央 HTTP 读取、桌面 SQLite 投影和 native UI 确认 1 个已配置供应商、3 个 chat 模型。14 项 Octop 持久化、角色、供应商 API 回归和 9 项 Yuxi 路由测试通过；类型、lint 和前端构建通过。真实连接测试未通过：现有中央 SiliconFlow 凭证包含非 ASCII 字符，需要管理员更新凭证，不报告模型推理成功。

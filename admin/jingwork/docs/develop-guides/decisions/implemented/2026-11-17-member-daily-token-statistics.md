# 成员累计、每日对话与实际 Token 用量

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/statistics_detail_repository.py

## 问题

管理员需要查看每个人累计及每日对话和 Token 消耗。桌面素材拥有提问和会话身份，企业模型调用在未启用积分计费时没有保存 usage，历史素材也没有 Token 字段。

## 决策

成员明细显示累计提问次数、累计独立会话数、时间范围内的提问与会话、输入及输出 Token，并提供每日表格、姓名搜索、排序及 CSV 导出。一次用户提问计为一次对话。每日会话按当天有消息的完整来源键去重，同一会话可以在多天出现。累计会话按全部记录去重。

Token 汇总已认证用户在统一企业模型入口发起调用时供应商返回的实际 usage，日期使用调用发生的北京时间日期。输入 Token 已包含缓存读取和写入量，总数使用输入加输出。历史缺失保持未采集，部分缺失显示已知用量及待补全调用次数。

IAM 企业目录补齐尚未登录或没有活动的成员。姓名来自 IAM，使用量通过 IAM 用户 UUID 派生的本地 UID 关联。成员与部门模式共用合并后的目录；尚未建立本地部门映射的账号归入未分配部门。退出目录但仍有历史使用记录的账号保留在明细中。

### 实现方案

统计 repository 独立聚合桌面事件与模型调用账本，按 UID 及调用发生日关联。统计 service 合并 IAM 目录及本地历史使用记录，再应用成员过滤和部门汇总。HTTP 接口维持超级管理员授权和有界日期查询。页面从组织概览的成员用量入口或数据统计的明细数据入口访问。

未启用积分计费时，统一模型调用在 ModelCreditCall 保存零预占的记录，使用 usage_pending、usage_recorded、usage_unknown 状态。用量结算在调用行锁内幂等更新。已记录的实际用量保留最终值，未知用量支持通过原有服务端核对接口补全。计费调用继续由既有预占和结算流程拥有余额事务。模型包装层的普通调用和流式结束都进入同一记录流程。

页面保留加载、查询错误和成员切换时的请求归属，过期每日响应无法覆盖新成员。CSV 导出对公式字符、控制字符和空白前缀进行转义。

## 替代方案

按字数换算 Token 不能表达上下文、工具调用及缓存成本。依赖客户端补传需要重新分发桌面版本。统一模型入口可按已认证用户保存后续实际用量。

## 后果

历史桌面素材缺少实际 Token，精确回填需要上游原始用量记录。企业入口之外的模型请求需要由其调用来源提供用量。模型调用次数与用户提问次数分别统计。成员及部门的既有时间筛选由[成员与部门统计](2026-10-07-statistics-details.md)记录。

## 验证

后台专项测试 16 项通过，涵盖真实 HTTP/PostgreSQL 的累计、范围、每日、上海日界、用户归属和独立 Token 聚合。真实 ManagedChatModel 到 PostgreSQL 的调用链路验证关闭积分计费时采集实际 usage、缺失用量、并发重复结算及余额访问隔离。IAM 目录单测覆盖零活动账号及成员和部门合计。

前端相关测试 12 项通过，覆盖累计字段、每日 UID 与日期、迟到响应、失败状态、未知和零 Token、CSV 公式及控制字符前缀。lint、ruff、生产构建和 diff 检查通过。

测试站的 IAM 全目录、成员累计值、每日提问合计、部门人数与独立 SQL 在只读一致性事务中核对。浏览器检查累计页面、每日弹窗、排序、成员搜索和 CSV 导出。发布后的真实模型请求产生实际 usage，数据库、成员累计、每日输入输出和导出文件中的 Token 逐项一致。工程信任检查仍报告既有 decision 元数据和缺失 workflow，文档构建的既有 design-qa 链接错误保留。

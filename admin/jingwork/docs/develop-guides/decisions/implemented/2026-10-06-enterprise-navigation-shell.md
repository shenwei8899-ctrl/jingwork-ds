# 企业管理导航外壳

用户要求在 Yuxi 增加与 Octop 企业后台相同的左侧管理菜单，并明确保留原有菜单、暂不填充业务内容。

采用独立 `/enterprise` 路由和 Vue 页面，复用 Octop 的菜单名称、层级和品牌资产，沿用 Yuxi 的管理员登录守卫。菜单选择通过 `page` query 表达；主内容区域为空。原 AppLayout 不变，品牌链接返回原知识库与技能页面。

未采用替换 AppLayout 或将 Octop 业务页面复制进来的方案，因为会改变原菜单或超出当前范围。此导航只提供视觉和选择交互，不声明业务能力已经接入。

验证：全量前端 lint 和 build 通过；真实浏览器确认页面、默认快速开始选中、分组展开、空白内容区。浅色桌面验证；其他主题与响应式尚未完整覆盖。


## 快速开始接入 Yuxi 原生智能体配置

后续授权将快速开始右侧实现为整页编辑器。AgentQuickstartEditor 复用原基本信息和 ShareConfigForm，运行配置使用 AgentRuntimeConfigForm 新增的可选 editor 输入；原弹框及聊天配置仍使用原 store 路径。

配置从 `/api/agent/backends/{backend_id}` 的用户资源 schema 和默认值生成。按 kind 分成模型、知识库、Skills（含预加载）、MCP、工具、子智能体、其他；原生工具分组保持原行为。每个字段只有一个企业菜单归属，未知后端字段进入其他配置。保留原资源全部/空选/隐藏项以及预加载 Skill 依赖规则。

整页使用独立草稿，菜单切换不销毁草稿，不改动当前聊天 Agent。创建将基本信息和完整 config_json.context 一次发送至原接口，保存后使用原 agent ID 回读；编辑更新同一记录。离开路由及企业 page query 切换时保护未保存内容。后端切换期间禁止再次切换。

验证：实际创建 enterprise-editor-check，读取预加载 knowledge-base 和摘要阈值 42；随后更新阈值为 43 并重载验证。新增分组完整性与草稿兼容测试；lint/build 和全量单元测试结果见本次 QA。未配置模型密钥，未验证实际推理。

最终检查：前端 lint:check、build 通过；全量单元测试 397/397 通过（0 失败）。

## 草稿与发布按钮

用户要求将保存改成保存草稿/发布。现有 Yuxi 无独立服务端草稿契约，当前草稿按账号和 Agent ID 存于当前浏览器 localStorage；恢复时检查版本与后端匹配，发布仍使用原创建/更新接口，成功后删除本地草稿。草稿未跨浏览器同步，也不改变服务器端的既有配置。UI 显示草稿未发布状态与本地保存提示。

实际浏览器验证草稿保存、刷新恢复和发布成功清理；lint/build 通过。

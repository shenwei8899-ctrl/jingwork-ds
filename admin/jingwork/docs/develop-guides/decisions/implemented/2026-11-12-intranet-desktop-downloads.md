# 内网桌面安装包下载

状态：implemented
类型：feature
Owner：web/src/content/downloads.js

## 问题

下载页的旧版本链接和根路径资源无法承接带应用前缀的内网部署，部分平台显示不可用或图标缺失。

## 决策

下载元数据记录实际安装包的版本、文件大小和 SHA-256，同源 URL 通过应用前缀映射。已发布文件存放在按版本组织的 `downloads/releases` 目录，并以只读目录挂载到 Web 服务。静态下载路由为缺失文件返回 404，支持浏览器断点续传。页面只启用 HEAD 响应类型与大小均匹配的安装包，未发布的平台不发起探测请求。

## 替代方案

外部对象存储地址需要额外网络入口与配置。安装包放入 Web 镜像会增加镜像体积，并使每次页面更新都复制安装包。

## 后果

安装包目录需要独立持久化。发布时先上传临时文件并核对 SHA-256，再将文件原子重命名为正式名称，最后更新页面元数据。不同版本使用不同路径，版本文件发布后保持不可变。个人授权保存在客户端用户配置中。

## 验证

下载页单元测试覆盖版本元数据、缺失文件、HTML 响应、大小不符与未发布平台。部署后验证三平台下载响应、Range 请求、完整文件 SHA-256，以及带应用前缀的真实页面。

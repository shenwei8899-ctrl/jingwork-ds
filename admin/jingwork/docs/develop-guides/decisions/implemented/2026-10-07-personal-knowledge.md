# 统一账号个人知识库

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/personal_knowledge_service.py

## 问题
桌面知识库使用本地开关与数据，无法与统一账号后台同步；后台文档接口阻断普通所有者。

## 决策
### 实现方案
`personal/databases` 的列表和创建用例复用 KnowledgeBaseManager 的 PostgreSQL 持久化。服务端从认证 uid 指定所有者和私有读取范围，创建模型拒绝额外身份或共享参数。管理后台继续读取同一存储，不增加异步复制。

桌面代理复用当前本地用户加密保存的统一登录会话，所有文档操作先重新读取个人库列表并验证所有权；桌面管理员也不能借后台管理权限跨账号操作。普通用户的文档接口只对本人创建的库开放，现有管理员接口仍执行资源 ACL。普通用户上传必须指定有管理权限的本人知识库。上传使用后台 MinIO，后台 worker 负责解析与索引。

独立部署保留原有本地页面；统一登录页面只操作后台数据，旧本地数据不做身份归属推断或自动迁移。

## 替代方案
本地创建后异步复制产生两份数据与权限事实，拒绝。直接开放管理员创建接口允许客户端指定共享范围，拒绝。

## 后果
新建默认私有，管理后台保留管理员授权及管理能力。沿用后台全局名称唯一约束，重名返回冲突。旧本地库仍保存在原数据库，尚未迁移到后台。

## 验证
真实 HTTP integration 覆盖两个普通账号创建、列表隔离、后台重新读取持久化结果、拒绝伪造 owner/ACL、文档上传与持久化记录，以及跨账号读取、删除和上传拒绝。新集成测试与既有管理员权限回归共 4 项通过（运行容器现有 superadmin 会话签名引导，未修改用户凭据）。

Octop 加密会话代理及原有企业会话测试共 5 项通过；界面测试 2 项通过，验证成功创建刷新后台列表、失败保留输入。前端 TypeScript/build 通过。新增 Python 文件 Ruff/mypy 通过；Octop 全局 Ruff 的 4 项既有 import 排序问题未纳入本改动。

# 按账号采集系统运行错误

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/runtime_log_service.py

## 问题

需要按用户定位操作中的运行报错，操作审计与对话历史不能替代系统诊断。

## 决策

管理后台日志管理增加系统日志。PostgreSQL runtime_error_logs 拥有错误事实；记录认证用户 ID、账号 UID、用户名快照、来源、操作、错误码、脱敏消息、关联 ID 与最近十步操作。普通用户只可通过当前认证身份上报，客户端不能指定身份；管理员才能查询，支持精确用户名、UID、ID、时间范围和 ID 游标分页。

后台中间件采集已认证 HTTP 失败和未处理异常，不缓冲 SSE，不保存请求/响应正文。桌面 API 包装器采集 HTTP/网络失败和最近十步 API 操作；模型包装器采集模型异常类型，不保存用户消息和供应商异常正文。传输失败不覆盖原始业务错误，记录类型明确的采集失败警告；离线没有持久重传队列，因此日志可能缺失。客户端记录是诊断报告，不作为可信操作审计。用户身份在服务端验证。

使用独立数据表，避免把诊断数据混入强制操作审计。新表由既有 metadata.create_all 幂等创建，不删除历史数据。错误字段限制长度、条数并脱敏；按用户每分钟一百条的计数限流用于保护存储，不是严格并发配额。当前不提供自动删除或无限制堆栈采集，后续可按业务保留期限添加清理。


## 替代方案

不复用操作审计表，避免诊断错误污染强制审计；不收集全部控制台和对话正文，以限制敏感信息进入日志。

## 后果

错误身份保存快照，不使用用户外键，账号删除后仍保留排障归属。增加独立索引表与管理员只读查询；桌面采集需要客户端更新。离线上报可能缺失，不承诺完整事件重放。

## 验证

独立 FastAPI 应用通过真实账号认证和 PostgreSQL 验证身份不可伪造、管理员限制、脱敏、筛选、游标分页和数据库回读；合成日志已清理。桌面采集单测验证无会话安全返回与不上传模型异常正文。

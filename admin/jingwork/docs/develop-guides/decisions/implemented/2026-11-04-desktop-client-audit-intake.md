# 桌面操作与系统日志采集

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/operation_log_service.py

## 问题

桌面操作需要出现在已有管理日志中。网络响应丢失会引发重试，账号切换也不能改变未发送记录的归属。

## 决策

### 实现方案

操作入口只接受操作枚举、结果和关联标识，认证依赖拥有用户身份。运行错误沿用系统日志入口，桌面端只提交错误分类与近期操作名称。两个 service 在既有表中提交事实后返回持久化 ID，以账号和关联标识取得 PostgreSQL 事务级 advisory lock，串行检查同一来源事件。

客户端私有队列保存来源账号，只有同一账号的凭据可发送其记录。确认前保留队列，确认后原子写入移除结果。后台管理页面读取原有 repository，无新增日志表或查询视图。

## 替代方案

客户端直接重放请求而不提供稳定标识会产生重复日志。允许客户端指定用户会破坏身份归属。独立日志表需要额外迁移和管理视图，现有字段足以保存这些有界事实。

## 后果

并发重试由 PostgreSQL 串行化，查询可读已提交记录。关联标识只能说明客户端声明的同一事件，客户端操作日志不替代后台业务事务内的强制审计。未登录时无法归属的错误保留于本地诊断，不推测用户身份。

## 验证

`test/integration/api/test_desktop_client_logs.py` 通过真实 HTTP 和 PostgreSQL 验证身份拒绝、普通账号提交、管理员查询、并发去重及跨账号隔离。客户端测试验证私有凭据、持久化确认及相同来源标识重试。

# 统一模型入口与用户积分额度

状态：proposed。类型：feature / architecture。

## 问题

桌面本地模型与后台模型配置分离，自动化无法沿用桌面已配置模型。已有 Token 观测不是扣费账本，不能阻止并发超额。用户要求管理员配置模型与用户额度，普通用户开箱即用，并接入 KeenLight 中转站。

## 决策

后台拥有模型凭据、用户/部门/全员模型分配、月额度、版本化价格、调用账本。桌面通过认证模型入口调用，不下发上游 Key。KeenLight 作为 OpenAI 兼容供应商，后台管理接口按用户提供的 Sub2API 源码契约对接 `/api/v1/admin`，使用管理员 Key 读取成员、成员 Key 和月用量。成员绑定不按姓名猜测，不自动创建账号。中转站美元账单和本地按人民币价目结算的积分分别保留，不能直接混算。100 积分对应 1 元；额度预占与结算在 PostgreSQL 同一事务加锁。用量缺失保留待核对预占，不当成零用量。首次实现手动配置、周期额度与明细，不接支付。

## 替代

直接下发供应商 Key 无法实施可靠的用户拦截。仅复用中转站账户限额会绑定特定上游，而且暂缺管理 API 契约。只按总 Token 扣除无法反映不同模型及缓存成本。

## 验收

- 普通用户不能修改模型权限、价目和配额，不能读取其他用户账单。
- 并发预占不可超过企业或成员额度；结算幂等，月切换不改写历史调用。
- 对话、自动化、子智能体与摘要执行均通过额度边界。
- 桌面用户不能通过模型覆盖绕过管理员分配，供应商 Key 不下发。
- 真实 PostgreSQL、HTTP、模型确定性回放及浏览器验证，未知用量保持待核对。

## 风险

外部网络取消可能已经产生费用，用量待核对需人工处理；执行模型输出上限用于限制预占风险。实际中转站价格与额外倍率必须以合同/后台事实配置，不使用公开宣传价格推算账单。
